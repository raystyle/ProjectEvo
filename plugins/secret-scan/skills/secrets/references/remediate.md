# 命中后处置

> 扫描器只报告。轮换与清史由人执行。

## 一、HIGH

1. 视该凭据为已泄露,到签发方轮换/吊销(即使提交已删)
2. 工作区改为环境变量或密钥管理器,从跟踪文件移除
3. 若曾推送远程:公开仓清史也清不掉已被爬的副本;私有仓可用 `git filter-repo` 或 BFG,再强制推送并通知所有 fork
4. 检查 CI 日志、issue、agent 会话记录是否又写了一遍明文

## 二、MED / LOW

打开命中行。占位符、文档示例、测试夹具走 `SECRET_SCAN_ALLOW`,不改 `rules.py`。`--pii` 的邮箱/手机误报多,默认关闭。

## 三、禁止

把完整密钥写进 issue、PR、diary、研究笔记、聊天记录。报告里的脱敏前缀足够定位。
