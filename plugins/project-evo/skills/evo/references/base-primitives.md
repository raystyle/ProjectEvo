# 根原语详解（四原语 + INDEX + AGENTS)

> 六个根文件的职责、模板头与维护规则。建骨架时逐个照抄模板头，填入本项目内容。

## 分工速记

`PRD.md` = 要什么；`GOAL.md` = 要达成什么；`PLAN.md` = 怎么做；`TODO.md` = 做到哪；`INDEX.md` = 去哪找；`AGENTS.md` = 听谁的。

需求驱动目标：新需求先入 PRD 走追问链，澄清后登记；GOAL 目标须回指 PRD 编号（D 编号）；实质推进当场更新原语。

## PRD.md（需求清单）

生命周期：

```text
新需求 → 待澄清 → 已澄清 → 已采纳 → 已交付
拒绝路径:任一状态 → 已拒绝(记原因防复问)
```

条目经**追问链**人机交互逐条澄清后登记，**禁止静默假设**。模板头：

```markdown
# PRD:需求清单管理
> 角色:需求清单,四原语之首:需求驱动目标。GOAL 的每个目标应能回指本清单条目。
> 分工:PRD=要什么;GOAL=要达成什么;PLAN=怎么做;TODO=做到哪。

## 需求清单
| 编号 | 需求 | 状态 | 澄清轮次 | 派生去向 |
| --- | --- | --- | --- | --- |
| D01 | (一句话需求) | 已交付 | 第 0 轮 | P0001;S001 |
```

维护要点：
- 一条需求一行，D 编号两位接续（D01、D02…）
- 「派生去向」回指 GOAL 锚点 / PLAN 切片 / P 编号 / S 编号
- 拒绝的需求保留行 + 已拒绝状态 + 原因（防复问）
- 追溯登记：项目中途补建 PRD 时，历史需求按时间线重建并标注 `[推断]`

## GOAL.md（目标管理）

四部分，**一目标一路径**：

| 段 | 内容 | 维护时机 |
| --- | --- | --- |
| 起点 | 何时发起、为什么发起、要解决什么问题 | 开工时写一句 |
| 锚点 | 当前锚定目标 + 推进时间线（倒序，最新在最上） | 每完成一个节点补一行 |
| 进程 | 只记当前这一个目标的进行状态 | 实时 |
| 历史 | 日期 + 目标 + 结果，倒序 | 目标达成后进程整条移入 |

原则：**一次只推进一个目标**；时间线一行一件事（日期 + 进展，含版本发布、阶段达成、坑修复）。

## PLAN.md（当前目标实施计划）

- 基于 `docs/research/`（为什么）与 `docs/references/`（怎么做）撰写；**每条挂依据来源**
- 含「完成的定义」：本目标的验收口径，逐条可核对，达成后标 `[实证: 日期 已达成]`
- 不存历史目标，目标完成即清空，内容已沉淀进 proven 与 diary

## TODO.md（进度清单）

当前目标的任务表：

```markdown
| 任务项 | 进度 | 说明 | 日期 |
| --- | --- | --- | --- |
```

目标完成后：过程与经验回填 `docs/proven/` 对应方案，起新清单。当天做的事只记 diary。

### CHANGELOG 与 ROADMAP 粒度纪律

- CHANGELOG 只留**版本级里程碑**：定位变更、发布、阶段完成、核心能力整体落地；细碎逐条不进，源头仓曾细碎逐条堆积，后被迫全删收敛 [经验： 源头仓 2026-08-29「CHANGELOG/ROADMAP 收敛为大版本里程碑」]
- ROADMAP 同口径：阶段与里程碑状态，不记任务流水

## INDEX.md（唯一索引）

只做定位，不做规则（规则权威源是 AGENTS.md):

1. **编号体系**：前缀定位 + 目录职能总述
2. **目录结构与代码文件位置**：逐文件职责表（代码文件也要）
3. **方案归档 / 研究文档 / references / guide / 错误速查**：各目录的编号登记表
4. **阶段与版本**：指向 ROADMAP 与 CHANGELOG

搜索方法（写进 AGENTS 文档索引段）：

```powershell
rg -n "关键词" INDEX.md                        # 1 先搜总索引
rg --files docs | rg 关键词                     # 2 按文件名搜
rg -n "关键词" docs\research docs\references    # 3 全文搜研究参考
rg -n "关键词" docs\mistakes\                   # 4 搜错误处理
```

新文档建成后必须登记进 INDEX 对应节，未登记等于不存在。

INDEX 维护硬规则 [经验： 结构源仓 09-03 重构实证]：

- **以磁盘为唯一事实源**：重写/对账 INDEX 时逐目录 `ls` 全量比对，不以旧索引为底稿（源仓曾因抄旧稿漏 5 个从未登记的 src 模块）
- **登记缺陷高发区**（定期对账）：diary 漏篇、`.tools` 漏件、src 新模块漏行、M 编号段不齐、P 断号无注记
- **断号注记**：编号跳号/退役在表下留一行注记（何时、为何），不静默留洞
- **TODO 残表清退**：目标完成后的旧任务表删除留指针（指向 proven 归档），不让残表堆积

## AGENTS.md（协作规则最高权威源）

四段结构（结构源仓 09-03 重构版，较三段多出意图路由节） [经验： 源仓 AGENTS 重写实践]：

1. **项目定位**：本质、边界、交互对象（根为定位）。边界写清楚「做什么、不做什么、质量承诺到哪」
2. **工作规则**：按场景分类（对话/操作/编码/文档），每类**先列动作清单，再定规则（可以/禁止/参考）**
3. **意图路由**：需求意图 到 命令/文档映射的**摘要层**，每条一行摘要，行为细则唯一权威指向对应 R 文档
4. **资源索引**：配合 INDEX 的搜索方法 + 分析路径（改产品行为先读 references 再回 research；规范禁令查 guide；踩坑查 mistakes)

**摘要层铁律**（防漂移）：意图路由只放一行摘要，细则唯一权威在 R 文档，双份并行必漂移（源仓曾 AGENTS 意图路由膨胀 57% 且与 R002 双份并行，5 处对账失守后瘦身重构） [经验： 结构源仓重构日记 2026-09-03]

`CLAUDE.md` 仅一行 `@AGENTS.md` 桥接，不重复维护（单一权威源）。

**大小软门禁**：AGENTS 目标 ≤8KB，超限即瘦身或下沉 references（源头仓 08-29 立规，skill 规范仓 同款 8KB 上限；实测家族各仓 8.9-16.7KB，门禁在压不在断，超了要有意识地收敛） [经验： 源头仓 2026-08-29 重构 + skill 规范仓 agent-files 规范]

操作规则段必含分平台 shell 约定（细节见 env-platform.md):

- 可以：Windows 命令用 PowerShell 7(`pwsh`);Linux / macOS / WSL 用该平台常规 shell；文档与源码 UTF-8;Windows 上需兼容 PowerShell 5.1 的脚本用 UTF-8 BOM
- 禁止：Windows 上默认用 `powershell.exe` 5.1 与 cmd；无 BOM 的中文 ps1 给 5.1 读；代码手拼路径分隔符

[经验： reader 仓 AGENTS 规则 2 原文口径]

### 文档义务表（AGENTS 维护，动作 到 必须对齐的文档）

| 动作 | 时机 | 义务 |
| --- | --- | --- |
| 新需求提出 | 提出时 | PRD 登记新行 |
| 追问链澄清（你问我答） | 澄清完成 | PRD 状态流转 + 澄清轮次与裁定（轮次算法见 flow-inquiry.md） |
| 目标立项 | 开工前 | GOAL 起点与锚点、PLAN 方案、TODO 清单 |
| 选型与调研 | 研究完成 | S 文档（六态）+ INDEX 研究节 |
| 写改源码与配置 | 改动完成 | README / SKILL 同步；行为基线变化同步对应 guide；版本级成果进 CHANGELOG |
| 写测试 | 新层或新面 | 测试规范 guide 同步（双轴分层与门禁见 flow-testing.md）；INDEX 测试行 |
| 写脚本 | 归档时 | `.tools/README.md` 清单行 |
| 出 PoC | 原型完成 | `poc/README.md` 登记表 + S 文档结论回填 |
| 踩坑 | 当场 | mistakes 接编一行；INDEX 错误节同步 |
| 方案达成 | 验收全绿 | proven 回填、GOAL 历史行、INDEX 归档节 |
| 每次提交 | 提交后 | diary 当天记钩子 |
| 发布 | tag 推送后 | CHANGELOG 封版、ROADMAP 阶段状态 |
| 文档结构变更 | 改名移目录后 | INDEX 同步；断链回归必跑 |

### 核心规则条款示例（按项目裁剪）

- 每轮对话先核对四原语；实质推进当场更新；踩坑当场落 mistakes
- 一次只推进一个目标；禁止偏离当前目标
- 问题与坑不留在对话里；不重复造已有规则
