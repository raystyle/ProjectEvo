# 五步工作流与自修正闭环

> 一个想法从登记到归档怎么走；主线执行中出问题怎么就地纠偏。

## 一、从登记到归档五步

1. **登记**：新需求先登记 PRD（状态「新需求」，走追问链澄清，禁止静默假设）；立项想法进 TODO（优先级 + 一句话 + 登记日）
2. **立项**：开工前先按 `docs\guide\template.md` 在 `docs\proven\PNNNN-短名.md` 写方案
3. **执行**：按方案实施步骤推进（拆步骤标准见下）
4. **验收**：按方案验收标准核对；PoC 看退出码；文档看清单与断链
5. **归档**：完成后 diary 记当天总结；方案回填「实施过程与经验」；版本/定位级成果另记 CHANGELOG；发版走 flow-release.md 封版流程；经验按分治细则落位（plan到proven、实证做法到references、踩坑到mistakes，见 exp-sedimentation.md)

## 二、拆步骤的标准

- **一步一件事**：每个 example / 测试 / 提交只证明一个部件
- **先方案后代码**：部件边界以方案为准；API 细节以对应研究与开发参考为准
- **每步带验收**：命令退出码、可核对输出；无验收标准的步骤先补标准再动手
- **依赖明确**：闸门不满足不开下一步

## 三、优先级与取舍

| 优先级 | 含义 | 处理 |
| --- | --- | --- |
| 高 | 用户点名 / 阻塞其它项 | 先做 |
| 中 | 高项绿了再做 | 排队 |
| 低 | 收尾件 / 明确延后 | 目标末尾或下目标 |

原则：**一次只推进一个任务目标**（见 GOAL 锚点）。

## 四、验收的通用口径

- 待办全部已完成或明确跳过（跳过须记原因，落 mistakes 或 TODO 说明）
- 交付物不触碰红线（方案「风险与回滚」节定义的禁止行为）
- 文档门禁通过（lint 零告警、断链回归、新文档已登记 INDEX)
- 研究与方案文档的关键结论标六态
- 高标准变更（规范重写、大重构）可加**多轮独立 review**：多家 agent 无头轮换各审一轮，直到「缺陷清零」；各轮抓出的缺陷家族沉淀 mistakes/research（源头仓三轮 kimi/codex/claude 实践：一轮抓多重 BOM 与陈旧引用、二轮抓口径与编号引用、三轮抓假插复核） [经验： 源头仓 2026-08-29 三轮无头 review]

## 五、过程内自修正闭环

> 主线执行中发现任何问题（文档错、规则缺、知识盲、行为坑），**不停主线另起炉灶**，就地走闭环：

1. **定位**：先搜 INDEX 与相关文档，确认是否已有规则、研究、参考覆盖，有则按既有口径办，没有才新增
2. **归类**：文档错修文档；规则缺补规则（AGENTS 或对应 guide）；知识缺落 research（六态）；出错模式记 mistakes（接编 MNNN）；验证过的做法沉淀 references
3. **修正**：改在源头；下游引用、索引、四原语同步
4. **验证**：lint + 断链回归；涉及结构再对账 INDEX 与磁盘
5. **提交**：一事一提交；diary 记钩子；主线继续

## 六、三条铁律

- **问题不留在对话或记忆里**：发现即落文档，否则下次还得重踩
- **不重复造已有规则**：动笔前先搜，已有覆盖就复用
- **临时补丁要么归档成正式资产、要么删掉**：不留半成品悬在仓里

## 七、沉淀铁律（与脚本/工具衔接）

同类手拼操作（命令序列、代码块）重复 **≥2 次**，必须沉淀：可重复执行的升级为 `.tools\` 下脚本（带自述与用法）；经验性的升级为 references 流程；约束性的升级为 guide 规范。

## 八、跨仓协作（姊妹仓校准）

多仓使用同一体系时，文档体系**不是一次设计定终身，是姊妹仓交替演化互相校准** [经验： 结构源仓 09-03 反向参考 reader 仓 重构]：

- **对齐通道**：跨仓 ISSUE 矩阵，四形态：通报（我改了什么）、依赖（我等你接线）、提议（建议你采纳）、上报（发现你的缺陷）；一仓一清单跟踪回音 [经验： ome 源仓 五仓 ISSUE 矩阵跑通完整一轮]
- **对齐清单形态**：跨仓差异整理成 R 文档对齐清单（如「源头仓 与 ome 对齐清单」），逐项收敛
- **探查先行**：对照姊妹仓形态前先两路探查（对方现状 + 本仓现状），比直接抄形态省一半返工
- **规范跨仓统一**：写作规范等全局规范变更时，向所有姊妹仓发 ISSUE 推动同步采纳，防口径分叉
