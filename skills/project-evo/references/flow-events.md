# 事件驱动执行模型：三态事件与超时兜底

> 程序流由事件决定，不靠轮询预定顺序；事件三分成功/失败/未知，未知（超时/无响应）最危险；每个等待必须有上限，超时把未知变成显式事件 [实证: 2026-09-04 熔断器维基与 let-it-crash 原文双源核对；EDP 正文四度超时未取，题录级]。

## 一、三态事件

| 事件态 | 含义 | 处置 |
| --- | --- | --- |
| 成功 | 任务完成，结果可信 | 消费结果，推进下一步 |
| 失败 | 明确没做成 | 错误路径：降级、重试、上报 |
| 未知（超时/无响应） | 不知道做没做成 | 显式处置；不无限等，不当失败盲目重试 |

- 未知不等于失败：超时的支付可能已扣款，处置靠幂等或探查，而非重掷 [推断]
- **let it crash（监督者模式）**：业务代码不防御未知状态，遇未见状态让进程崩溃，崩溃即事件上报 supervisor，按预定义策略处置；未知态处理从业务代码剥离到监督层 [实证: let-it-crash 原文]
- 与知行合一的接口：知必落行，行必产事件；程序听回声推进，不靠猜 [推断]

## 二、事件驱动执行（家族实盘）

- hook 事件对：PostToolUse（成功）/PostToolUseFailure（失败）驱动后续动作，hook 带 timeout 字段 [实证: 本仓 settings.json 实配]
- 事件喂状态：结构源仓 hook 吃 stdin 事件 JSON 写 state 文件 [实证: 该仓 R004]
- 监督者自愈：浏览器工具仓 x-monitor 的 supervisor 监听异常自动重启，心跳文件判生死 [实证: 该仓 SKILL]
- 后台任务通知驱动主流程继续；子代理断连即失败事件，主流程换路径降级 [实证: 2026-09-04 会话两次实录]

## 三、超时兜底三选

铁律：**每个等待必须有上限**。超时后三选：

1. **重试一次**：幂等前提；冷启动类瞬时故障重试即过 [实证: browser-harness 复测通过]
2. **换路径**：输出管道坏换载体，信源坏换镜像
3. **放弃并记录**：保持未知，标 `[假设]` 附复核路径，不伪造结局

进阶熔断三态：Closed（放行）/Open（连续失败快速失败）/Half-open（冷却后试探，成则回 Closed）；防重试风暴；Half-open 即带验证路径的一次试探 [实证: 维基原文]。与假绿防线同构：崩溃显式上报，对应 FAIL 必 exit 1、错误不吞 [推断]。

## 四、与六态的接口

成功事件是 `[实证]` 渠道（测试绿、退出码 0）；失败事件进错误路径（mistakes、回归用例、门禁 FAIL）；未知事件即中转态，兜底是收尾处置纪律的运行时形态 [推断]。
